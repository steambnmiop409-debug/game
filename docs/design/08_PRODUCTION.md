## T1. 엔진과 기술 스택 (확정)

### T1.1 확정: 웹 (TypeScript + Three.js + Web Audio API + Vite)

| 이유 | 설명 |
|------|------|
| 발디 문법에 맞다 | 박스형 공간, 최근접 필터 텍스처, 빌보드 스프라이트는 Three.js로 간단하고 가볍게 만들 수 있다 |
| **박자가 생명이다** | Web Audio API의 오디오 시계(`AudioContext.currentTime`)로 소리를 **샘플 단위로 정확하게 예약**할 수 있다. 펜듈럼, 발소리 차폐, 시퀀서를 하나의 시계에 묶는 데 유리하다 |
| 입체음향 | `PannerNode`의 HRTF 모드로 헤드폰 입체음향을 낼 수 있다 (무박자 챕터에서 크리처 위치를 소리로 읽는 데 필수) |
| 마이크 (선택) | `getUserMedia`로 최종장의 '내 목소리로 A 부르기'를 구현할 수 있다 |
| 배포 | 링크 하나로 브라우저에서 바로 플레이할 수 있다 (GitHub Pages, itch.io) |
| 개발 환경 | 이 저장소의 클라우드 환경에서 헤드리스 크로미움으로 **직접 실행하고 화면을 확인하며** 개발할 수 있다 |

### T1.2 검토했던 대안 (기록용)

| 대안 | 장점 | 단점 |
|------|------|------|
| Unity | 발디가 실제로 만들어진 엔진. 데스크톱 배포가 쉽다 | 이 클라우드 환경에서 실행·검증이 어렵다 |
| Godot 4 | 무료, 오픈소스, 데스크톱 내보내기 | 오디오를 샘플 단위로 예약하려면 추가 작업이 필요하다 |

> 웹으로 시작하더라도 **나중에 Electron이나 Tauri로 감싸 데스크톱판**을 만들 수 있다.

## T2. 아키텍처: "시계는 하나다"

```
                    ┌──────────────────────────┐
                    │   Conductor Clock (펜듈럼)  │  ← AudioContext.currentTime 기반
                    │   BPM, 박자 번호, 다음 틱 시각  │     미리보기(lookahead) 예약
                    └─────────────┬────────────┘
        ┌──────────┬──────────────┼──────────────┬──────────────┐
        ▼          ▼              ▼              ▼              ▼
   [Sequencer]  [Beat AI]    [Noise System]  [Light Pulse]  [HUD Metronome]
   음악 레이어   적이 박자마다    발소리 차폐       틱마다 3%       진자 아이콘
   샘플 재생     한 칸 이동       판정 (±90ms)     밝기 변화
```

| 모듈 | 책임 |
|------|------|
| `core/clock` | 펜듈럼. BPM 변경과 루바토, 박자 이벤트 발행 |
| `audio/sampler` | 실제 악기 샘플을 음높이별로 재생 (센트 단위 미세조정 포함). 살아 있는 악기는 **악기 층 + 사람 소리 층** 두 겹을 함께 재생하고, 사람 층 크기를 챕터 값으로 조절한다 (S1.2) |
| `audio/sequencer` | 악보 데이터를 박자에 맞춰 예약 재생 (S7) |
| `audio/fx` | 레트로 신호 체인, 공간 잔향, 귀 막기 저역통과 |
| `audio/pitch` | (선택) 마이크 음높이 감지 (자기상관 방식 계열) |
| `world/level` | **텍스트(ASCII) 격자 지도**를 3D 박스 공간으로 변환 |
| `render/billboard` | 스프라이트, 외곽선, 프레임 애니메이션 |
| `ai/` | 크리처 상태 기계 (G3.2), 박자 묶임과 무박자 이동 |
| `systems/` | 소음, 숨, 이명, 공명기와 신호표(G5.3), 가방, 룰라, 선생님/친구 수치(G10) |
| `ui/` | 성적표, 연습일지, 메뉴(계명) |

**레벨 파일 예시 (설계 형식)**

## T3. 에셋 파이프라인

| 에셋 | 방법 |
|------|------|
| 텍스처 | **팔레트 인덱스 텍스트 → PNG 변환 스크립트.** 나무결, 펠트, 타일 같은 반복 재질은 절차적 생성 스크립트(Python/PIL)로 만들고, 포스터·얼굴·아이 그림은 픽셀 단위로 직접 그린다 |
| 스프라이트 | 위와 같은 형식. 프레임마다 별도 파일, 외곽선은 스크립트가 자동으로 넣는다 |
| 로고 | `tools/brand/make_logo.py` → `assets/brand/offkey_logo.svg` (이미 시안 있음) |
| 음악 | 악보 데이터(JSON) → 실시간 시퀀서. 구조 스케치는 MIDI (`tools/audio/make_theme_sketch.py`) |
| 샘플 | 직접 녹음 + CC0 라이브러리 (S10.1). `assets/audio/samples/<악기>/<음>.ogg` 규칙. **라이선스는 `assets/audio/LICENSES.md`에 출처와 함께 기록** |
| 텍스트 | 한국어·영어 문자열 테이블 (기록물, UI, 자막) |

## T4. 마일스톤

> 파피 플레이타임 같은 챕터 게임은 챕터 하나에도 큰 작업량이 든다. 그래서 **'핵심 감각' → '챕터 1 완성' → 나머지 순서**로 쌓는다.

| 단계 | 목표 | 산출물 | 성공 기준 |
|------|------|--------|----------|
| **M0 핵심 감각 프로토타입** | "박자에 맞춰 걷는 것이 재미있고 무서운가?" | 복도 1개와 방 3개, 펜듈럼 틱, 발소리 차폐, 박자마다 걷는 티코, **소리굽쇠 '멈춤' 신호**, 핀 잠금 1개, **숨 쉬는 피아노 1대**(사람 소리 층 시험), 메인 테마 시퀀서 v0 | 처음 하는 사람이 설명 없이 5분 안에 '박자 걷기'를 알아채고, 숨 쉬는 피아노 앞에서 **소리만으로** 불쾌감을 느낀다 |
| **M1 Ch1 버티컬 슬라이스** | 챕터 1을 처음부터 끝까지 | P0 + P1 전체, 타이틀, 메뉴, 저장, 설정, 접근성, 로고, 메인 테마 완성본 | 처음부터 끝까지 45~60분, 크래시 없음 |
| M2 Ch2 | 연습동 | 음높이 다이얼, 박수·자 신호, 허락받은 연주, 졸업 게시판, 그랑데, 싱어롱즈 | 플레이어가 '졸업'의 뜻을 스스로 번역해 낸다 |
| M3 Ch3 | 지하 공방·양호동 | 무박자 AI, 역재생, "쉿" 신호, 신호 연쇄, 휴식실(무향실), 너스 허시, 미완성품들 | 피 한 방울 없이 가장 불쾌한 챕터 (B6 검수 통과) |
| M4 Ch4 | 스튜디오와 시계탑 | 겹쳐 쌓기, 고장난 악단, 졸업생들, 감시 카메라 테이프, CD-ROM 미니게임, 티코 최종 추격 | |
| M5 Ch5 | 발표회장 | 후원자들의 박수 차폐, 프리마의 루바토, 오르간 스톱, 킨더클라비어, 「집에 가는 노래」, 엔딩 3종, 선택 마이크 | |
| M6 다듬기 | 전체 | 다국어, 성능, 플레이테스트 반영 | |

**오디오는 병행 트랙으로 진행한다:** M0에서 시퀀서와 샘플러 → M1에서 메인 테마와 Ch1 크레딧 송 → 이후 챕터마다 테마 하나와 크리처 시그니처.

## T5. 리스크와 결정이 필요한 사항

### T5.1 리스크

| 리스크 | 대응 |
|--------|------|
| 샘플 라이선스 | CC0와 직접 녹음을 우선한다. 출처와 라이선스를 파일 단위로 기록한다 |
| 브라우저 오디오 자동재생 정책 | 첫 클릭이 있어야 오디오가 시작된다 → **"소리굽쇠를 두드려 시작하세요"** 화면이 이 제약을 게임의 의식으로 바꾼다 (B3.4) |
| 스피커와 헤드폰 차이 | 32피트 저음은 진폭 변조로 흉내 낸다 (S6). 첫 실행 때 헤드폰 사용을 권장한다 |
| 박자 은신이 어렵게 느껴질 위험 | M0에서 가장 먼저 검증한다. 차폐 구간 폭과 '박자 걷기 보조'로 조정한다 |
| 범위 폭증 | 챕터 단위로 출시할 수 있게 만든다. Ch1만으로도 완결된 경험이 되게 한다 |
| 아동 소재의 민감성 | 바디 호러를 다루므로 B6 표(보여 준다 / 암시만 / 절대 하지 않는다)와 A1.3 시각 규칙을 모든 스프라이트·기록물의 검수 기준으로 쓴다. 접근성 옵션 '흔적 표시 줄이기'를 M1부터 넣는다 |

### T5.2 결정이 필요한 사항 (사용자 확인)

1. ~~**엔진:** 웹 / Unity / Godot~~ → **TypeScript + Three.js 확정**
2. **첫 범위:** M0 프로토타입부터(제안) / 바로 Ch1 버티컬 슬라이스
3. **언어:** 한국어 우선 + 영어 병기(제안) / 한국어만
4. **마이크 기능:** 최종장 선택 기능으로 넣기(제안) / 넣지 않기
5. **실물 녹음:** 직접 녹음할 악기(종이띠 오르골, 장난감 피아노 등)와 사람 소리 층(허밍, 숨)을 준비할 수 있는지, 아니면 CC0 샘플과 합성만으로 갈지
